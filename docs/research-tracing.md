# Трассировка антиспама для НИР

Реализация целиком на TypeScript. Трассировка измеряет существующий ансамбль,
не меняет его веса, пороги, правила модерации или условия включения ACTIVE.
SQLite автоматически мигрирует со схемы 8 на 9 при открытии `SpamStore`.
Новая таблица `inference_traces` связана со снимком сообщения и предсказанием.
Старым предсказаниям вымышленные замеры не добавляются: сбор начинается после обновления бота.

## Что сохраняется

Одна JSON-запись описывает попытку обработки конкретной редакции сообщения.
В SQLite сохраняется первая попытка для пары «снимок сообщения, версия модели»;
повтор доставки уже обработанного update не создаёт новое измерение.
При холодном старте версия равна `null`, поэтому последующая обработка с моделью
может получить отдельную запись. При редактировании создаётся новый снимок и трасса.

| Поле | Значение |
| --- | --- |
| `schema_version`, `trace_id` | Версия контракта трассы и UUID попытки |
| `chat_id`, `message_id` | Группа и Telegram ID; идентификатор сообщения уникален внутри группы |
| `database_message_id`, `revision` | Снимок в локальной БД и номер редакции |
| `started_at`, `completed_at`, `message_created_at` | Время UTC в ISO 8601 |
| `model_version`, `model_format` | UUID сохранённого артефакта и версия его формата |
| `normalizer_version`, `context_policy_version`, `pipeline` | Версии нормализации и алгоритма |
| `dataset_size`, `dataset_spam`, `dataset_normal` | Размер корпуса модели после отбора и дедупликации, включая train и validation |
| `train_size`, `validation_size` | Размеры частей корпуса модели; это не текущий размер всей SQLite-базы |
| `mode`, `threshold`, `protected_user` | Политика на момент решения и признак защищённого автора |
| `seen_in_training_or_validation` | Совпадение с train/validation по хешу или по известному в БД reduced text |
| `duplicate_group` | SHA-256 reduced text для группировки повторов при подсчёте метрик |
| `runtime` | Версия Node, платформа и архитектура процесса |
| `prediction_id`, `predicted_label` | ID прогноза и класс при действовавшем пороге |
| `final_spam_score`, `final_normal_score` | Итоговый score и его дополнение до 1; не калиброванные вероятности |
| `true_label`, `true_label_source`, `labelled_at` | Актуальная ручная разметка на момент экспорта либо `null` |
| `label_is_prospective`, `exported_at` | Получена ли разметка после начала попытки; время выгрузки |
| `stages` | Упорядоченные этапы, длительности и результаты |
| `outcome`, `deletion_status` | Итог вычисления и действия; текущий статус попытки автоматического удаления |

Для cold start и прерванных попыток часть полей отсутствует или равна `null`.
`true_label` не берётся из прогноза, SHA-совпадения, bootstrap или факта удаления.
Он читается из текущей ручной разметки при экспорте. `/spam undo` изменит следующую
выгрузку, но не уже созданный файл. Разметка относится к конкретному снимку текста,
а не автоматически ко всем редакциям Telegram-сообщения.

## Результаты этапов

Каждый элемент `stages` содержит `stage`, `status`, `duration_ms`,
`started_offset_ms`, `result`. Статус — `completed`, `skipped` или `error`.
У пропущенного этапа длительность `null` и есть причина пропуска.
Ошибка не выдаётся за нулевую длительность или нормальное сообщение.

1. `model_loading`, `research_snapshot`: получение модели и сведений о корпусе.
2. `sha256_lookup`: совпадения **нормализованного** текста в этой группе,
   количество совпавших снимков и доверенных spam/normal-меток, наличие конфликта.
   Собственные редакции исключены. `match_score: 1` означает совпадение хеша,
   а не вероятность спама 100%. Это диагностический поиск: `terminal: false`,
   `used_in_decision: false`. Дальше алгоритм продолжает работать.
3. `normalization`: хеш, версия нормализации, длина нормализованного текста.
4. `char_tfidf`, `word_tfidf`: число ненулевых признаков и размер словаря.
   `numeric_features`: значения числовых признаков после масштабирования.
   Эти преобразования не являются отдельными классификаторами, поэтому у них
   `spam_score: null`, а не придуманная уверенность.
5. `logistic_regression`: оценка LR. `logit_attribution` отдельно показывает
   вклад char, word, numeric и intercept в линейный аргумент сигмоиды:

   `z = b + Σ_char(wᵢxᵢ) + Σ_word(wᵢxᵢ) + Σ_numeric(wᵢxᵢ)`;
   `score_LR = 1 / (1 + exp(-z))`.

   Положительный вклад увеличивает score, отрицательный уменьшает.
   Вклады складываются в пространстве логитов, а не процентов.
   Это объяснение одной совместно обученной LR, не качество отдельно обученных моделей.
6. `markov`: число переходов, порядок 3, сглаживание α=1, размер алфавита,
   средние логарифмы правдоподобия для spam/normal и их разность `d`.
   Сохраняется `score_M = sigmoid(d)`. Это сигнал языковой модели,
   не эмпирически калиброванная вероятность класса.
7. `lr_markov_blend`: промежуточный score `B = 0.9·LR + 0.1·M`.
   Если Markov не дал результата, используется LR с весом 1.
8. `telegram_permissions`: время ожидания проверки прав автора.
9. `context_database`, `similarity_vector`: извлечение контекста и подготовка вектора.
10. `similarity`: максимальные cosine similarity к spam и normal,
    ID найденных эталонов и число просмотренных эталонов.
    Две similarity не обязаны давать в сумме 1. Это сходство, не вероятность.
11. `campaigns`: число похожих авторов, ID сообщений, число кандидатов и score кампании.
12. `behavior`: наблюдавшиеся сообщения автора, частоты, время вступления,
    повторы, общие URL с другими авторами и поведенческий score.
13. `final_ensemble`: `F = B + (1−B)·(0.2·S + 0.15·C + 0.1·U)`, где
    `S = 1`, если spam similarity ≥0.95 и превосходит normal similarity более чем на 0.02,
    иначе `S = 0`; `C` и `U` — действующие сигналы кампании и поведения.
14. `runtime_policy`, `diagnostic_ablations`, `decision`, `prediction_database`:
    действующий режим/порог, диагностические сравнения, фактическое решение и его запись.
15. `active_action` или `telegram_review_card`: результат и время внешнего действия,
    либо причина отсутствия карточки. `outcome` отделяет класс сообщения от действия:
    высокий score у защищённого автора не означает удаление.

У этапов с `spam_score` поле `normal_score` означает `1−spam_score`.
`calibrated_probability: false` явно запрещает трактовать эти значения как проверенную
вероятность. Для диагностического класса LR, Markov и промежуточных ансамблей
используется порог 0.5, записанный рядом с результатом. У `decision`, итоговых полей
и сравнений в сводном отчёте используется фактический порог политики.

## Как понимать время

`performance.now()` измеряет прошедшее монотонное время в миллисекундах,
не CPU time. `duration_ms` относится к указанному вычислению; ожидания Telegram
и запросы БД имеют отдельные этапы. Markov включает повторную нормализацию,
которую выполняет существующий алгоритм. Similarity/кампании включают подготовку
векторов эталонов при промахах кеша. Поэтому первый и последующие вызовы могут отличаться.

`total_duration_ms` начинается **после** capture, observe и проверки повтора предсказания;
заканчивается после действия бота, перед окончательной записью трассы.
Включает ожидания, диагностику, накладные расходы измерения и промежуточную запись
перед внешним действием. Время доставки Telegram update и ожидания в очереди не входит.
`compute_stage_duration_ms` — сумма перечисленных вычислительных этапов
(normalization, признаки, LR, Markov, blend, similarity_vector, similarity, campaigns,
behavior, final_ensemble, decision). Это не полное время без сети и не замер CPU:
диагностика, сбор метаданных, запись, часть сборки вектора и прочие расходы туда не входят.

Перед внешним действием сохраняется checkpoint `action_pending`, затем он обновляется.
При остановке процесса может остаться частичная трасса; её нельзя считать завершённой.
Ошибки записи трассы журналируются как `antispam_trace_write_failed` и не изменяют
решение модерации. Таким образом, журнал не гарантирует полноту при сбое диска/БД.
Не все Telegram updates проходят inference: команды, исключённые авторы и сообщения,
которые не принимает capture, не являются знаменателем этих метрик.

## Выгрузка

Из корня проекта, с той же конфигурацией `.env`, что у бота:

```powershell
node src/antispam/exportResearch.ts -1001234567890 ./experiment-001.jsonl
```

Заменить ID на группу из `ANTISPAM_CHAT_IDS`. Нужна версия Node с поддержкой запуска
TypeScript и `node:sqlite`, как для существующих тестов проекта.
Команда создаёт два новых локальных файла:

- `experiment-001.jsonl` — до 10 000 последних трасс группы, одна JSON-запись на строку;
- `experiment-001.jsonl.summary.json` — агрегаты по версии модели, версии контекста,
  режиму, размеру корпуса и порогу.

Существующие файлы не перезаписываются; при ошибке записи возможны частичные файлы,
поэтому успешность подтверждает итоговый вывод команды. Записи выдаются от новых к старым.
Для выбора другого лимита доступен программный `exportResearch`, от 1 до 100 000.
Без `--include-text` исходные тексты не экспортируются. Флаг добавляет `raw_text`
для просмотра примеров. Даже без текста остаются ID группы/сообщений и хеши:
это не анонимизированная публикационная выборка.
Трассы удаляются вместе со снимками по существующему retention. Для сохранения
эксперимента экспортировать их до истечения срока хранения.

## Метрики и сравнение компонентов

Сводка содержит количество трасс и исходов, ошибки и пропуски этапов,
число допустимых размеченных трасс, mean/p50/p95/min/max длительности и размер выборки `n`.
Перцентили используют nearest rank: элемент с номером `ceil(p·n)` в отсортированном ряду.
Длительности ошибок остаются в JSONL; агрегаты времени этапов используют завершённые этапы.

Качество рассчитывается только для завершённых попыток с предсказанием,
ручной разметкой после начала обработки, незащищённым автором и без известного
пересечения с train/validation. Повторы reduced text считаются один раз:
берётся первый в экспорте, то есть последний по времени пример; конфликтующие метки
исключают группу целиком. После retention прежние reduced-text варианты могут быть
недоступны для поиска пересечений; хеши train/validation в артефакте продолжают проверяться.

Сравниваются `lr`, `markov_only`, `lr_markov`, `lr_markov_similarity`,
`lr_markov_similarity_campaign`, `full` и `without_markov`, `without_similarity`,
`without_campaign`, `without_behavior`. Это вычисления на тех же наблюдениях
с фиксированными весами и единым порогом. Они не выполняют дополнительные действия бота.
Если компонент не дал score, соответствующий вариант не получает выдуманный прогноз.

Из матрицы ошибок:

- `precision = TP / (TP + FP)` — доля спама среди предсказанного спама;
- `recall = TP / (TP + FN)` — доля найденного спама;
- `F1 = 2TP / (2TP + FP + FN)`;
- `FPR = FP / (FP + TN)` — доля ошибочно отмеченных нормальных сообщений.

При нулевом знаменателе метрика равна `null`. Отсутствие разметки не означает
нулевой FPR. `eligible_labelled_traces` считается до дедупликации, `variants.*.n` — после.

Этот отчёт позволяет наблюдать, как меняется результат текущего ансамбля при отключении
сигналов. Он сам по себе не доказывает улучшение: администраторы обычно размечают
подозрительные сообщения чаще остальных, а веса и пороги отдельных моделей здесь
заново не подбираются. Для вывода в НИР нужна также независимая выборка нормальных
сообщений и спама, заранее определённый способ отбора, сопоставимые группы/периоды,
зафиксированные версии и достаточное число наблюдений. Для сравнения отдельно обученных
char-only, word-only и других моделей потребуется отдельный эксперимент с переобучением.
Текущая сводка не заменяет существующую процедуру проверки и ручного включения ACTIVE.
